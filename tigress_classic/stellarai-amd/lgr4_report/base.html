LGR4 CRMHD restarts from t = 450 with the shear-face limiter

We restarted the 8 pc LGR4 cosmic-ray MHD production run at t = 450 with the shear-face positivity limiter (ε = 0.5) and new history columns that record every numerical correction. A second run starts from the same state refined to 4 pc. This page records how the code was built, how the restart files were made, how the jobs were run and post-processed, what went wrong along the way, and how the runs are behaving.

Summary movie

Findings so far

  • Both runs are healthy. They have no crashes, NaNs or stalls. The error logs hold only the usual messages: the dual-energy correction capped at 1% (4k–57k per segment, rising and falling with supernova activity), sink-particle mass return and formation (including an occasional “accretion rate is negative” notice when a new sink forms, 99 in 4 pc segment 2, 18 in segment 6 and 311 in one burst at t ≈ 538.7, each handled without effect), and population synthesis running short of gas mass.
  • The limiter removes most of the density-floor mass. Over 450 → 451 at 8 pc, the floor adds 57 mass units with ε = 0.5 against 1261 with the limiter off, 22× less. Over the whole 8 pc run the density floor adds 4e-6 of the gas mass in total.
  • The ceiling is now the largest numerical correction, and the limiter does not change it. Ceiling mass is 1–4e-6 of the gas mass per time unit. The energy the ceiling removes is 9–20% of the energy lost to cooling at 8 pc. At 4 pc, in 5-unit windows, it was 2–7% while supernova activity was low (t ≈ 450–485), rose to 14–22% at t ≈ 485–500, and has stayed at 9–17% since t = 500. So it follows the supernova rate, not the resolution.
  • Bad-density cells come in bursts, and the original run had them too.
    • 8 pc peaks at 6e-6 per cell update (t ≈ 495–500). 4 pc peaks at 1e-5 (t ≈ 480–485).
    • The original production run averaged 2.5e-7 over 450–500, with its own bursts.
    • The bursts add almost no floor mass: the bad cells are repaired by neighbour averaging.
  • Bad-pressure cells are about 4× rarer than in the original production run. The rate is 6.4e-3 against 2.4e-2 per cell update at t = 450–451. The limiter is not the cause: the master-based A/B test gives 6.4e-3 with or without it. The difference comes from changes to the code since the July production build.
  • The physical evolution stays within the range of the original run. Star formation, outflow and energies drift apart from the original after a few time units. That is expected: the supernova random draws are now hash based, so the runs diverge from the first cluster supernova onward.

Code: the run branch

Repository PrincetonUniversity/tigris, branch lgr4-crmhd-run (pushed). The executable was built from tip 7ab66b084. The branch starts from origin/cr-shear-face-limiter (tip 9fee4772f, which adds the hydro and CR shear-face positivity limiters) and merges in three more branches:

CommitWhat it brings
2f798e48dConservative positivity limiter for the shear-face flux (hydro): <hydro> shear_flux_limiter, shear_flux_limiter_eps
9fee4772fThe same limiter for the CR energy: <cr> shear_flux_limiter, shear_flux_limiter_eps
6c20e18caMerge origin/fix-floor-small-bugs. Neighbour flooring takes the fallback velocity from the previous state (fc414f76d), the neighbour-averaged internal energy skips density-floored neighbours (74fd515b7), and FOFC applications are counted over all stages (6c9636247).
7d8737c97Merge origin/fix-ceiling-scalar-bound: bounds the composition (passive scalars) of the mass the ceiling adds (d0a19b1c4)
ca793dcc2Merge history-numerical-additions, which records floor and ceiling additions (dm_floor, de_floor, ds*_floor, dec0_floor, de_ceil, ds*_ceil), stage-weighted face mass fluxes (dm_x1i…dm_x3o) and supernova mass (m_sn, m_sn_rw, m_rw_launch). The columns are enrolled after all others, so the restart layout is unchanged.
7ab66b084Records the fallbacks of the CR source-term update: de_crsrc and n_crsrc_eg (gas-energy guard), dec0_crsrc and n0_crsrc (CR energy reset when it would go negative or NaN). Only tigress_classic enrolls them; tigress_ncr does not.

To recreate the branch:

cd ~/tigris
git worktree add -b lgr4-crmhd-run .worktrees/lgr4-crmhd-run origin/cr-shear-face-limiter
cd .worktrees/lgr4-crmhd-run
git merge --no-ff origin/fix-floor-small-bugs        # clean
git merge --no-ff origin/fix-ceiling-scalar-bound    # clean
git merge history-numerical-additions                # conflict in src/feedback/feedback.cpp (see below)
# then commit 7ab66b084 (CR source-term fallback tracking)
# or simply:  git worktree add .worktrees/lgr4-crmhd-run origin/lgr4-crmhd-run

The one merge conflict was in src/feedback/feedback.cpp. The ParticleManager refactor on the limiter branch had renamed the supernova lists to member variables. The resolution keeps the new members (all_fii_, all_firi_, num_sn_) and adds the pmb->sn_mass[0/1] lines that record supernova mass.

Differences from master that matter for tigress_classic:

  • Supernova random draws are hash based (2740445ef), so cluster supernovae diverge from master from the first event onward. Runaway supernovae match exactly.
  • Accretion no longer depends on particle order (348f3e284).
  • The <random> restart block is rebuilt by name, so old checkpoints restart cleanly.

None of this makes results bit-for-bit reproducible against master, and it was not meant to.

4 pc: refined offline with tigris_tools

Refinement inside Athena is awkward for this setup, so we used refine_restart from changgoo/tigris_tools (commit bf37dc2, "Fix non-cubic restart block ordering"). Dry runs (--dry-run) with block sizes 32³, 64×32×32, 64×64×32 and 64³ all passed. We chose 64×64×32, which gives 1536 blocks and so 1536 ranks on 16 nodes.

refine_4pc.slurm (job 1411, 16 s) 
#!/bin/bash
#SBATCH --account=eost
#SBATCH --partition=cpu
#SBATCH -N 1
#SBATCH --ntasks=1
#SBATCH --cpus-per-task=4
#SBATCH --mem=64G
#SBATCH --time=06:00:00
#SBATCH --job-name=refine4pc
#SBATCH --output=%x-%j.out
#
# Refine the 8 pc CRMHD checkpoint (t = 450) to 4 pc with tigris_tools/refine_restart.
#   128x128x1536, 32^3 blocks (768)  ->  256x256x3072, 64x64x32 blocks (1536 ranks)

BASE=/scratch/gpfs/EOST/changgoo/tigress_classic_sync
IN=$BASE/rst/crmhd.00014.rst
OUT=$BASE/rst/crmhd-4pc-mb64x64x32.00014.rst

cd $BASE
module purge; module load anaconda3/2026.7
export PYTHONPATH=$HOME/tigris_tools/src
git -C $HOME/tigris_tools log -1 --format='tigris_tools %h %s'
date
python3 -m tigris_tools.refine_restart $IN $OUT --refine 2 --block-size 64,64,32 --verify -v
echo "EXITCODE=$?"
date
ls -la $OUT

Verification.

  • --verify passed: header, block size, block order and file size are all consistent.
  • Totals over active cells (mass, three momenta, total energy, the four CR components, five scalars) match the 8 pc file to about 1e-15.
  • div B is about 1e-12 relative.
  • All 3246 particles carried over with the same IDs.
  • Cell-averaged magnetic energy is 0.27% higher, taken from internal energy. That is expected for this kind of refinement and harmless with dual energy.

Output: rst/crmhd-4pc-mb64x64x32.00014.rst (43,452,422,820 bytes), with the same t and cycle as the source.

Restart tests

Before production, one-time-unit restarts (t = 450 → 451) from the same checkpoints compared the old master-based build with the run build, limiter off and on. They ran with tigress_classic_sync/test_run.slurm, which writes only history output and deletes the final restart file.

  • The CR source-term fallbacks are small. The gas-energy guard never fired (de_crsrc = 0). The CR reset fires about 162k times per time unit and changes the CR energy by about 1e-5 of Ec per time unit.
  • The run build is 5% faster than the master-based build (1156 vs 1214 s per time unit). The ε = 0.5 limiter costs a few percent per cycle.

    • 1.0e5 with ε = 0.1;
    • 1.0e4 with ε = 0.5;
    • 4.7e5 with the boundary-sync fix.
    So ε = 0.5 with the limiter alone was chosen, without the sync fix.

Production jobs

Scripts: ~/tigris_scripts/tigress_classic/stellarai-amd/tigress_classic_LGR4_crmhd_{8,4}pc_rst.slurm. Each one copies the executable, build info, script and cooling tables into the run directory and writes the limiter switches to athinput.restart_add. It runs to the Athena wall-time limit (-t 23:30:00), resubmits itself with -r on exit code 3, then submits the post-processing job. The first segment resets the history and particle-history file numbers so those files start fresh in the new directory. The 4 pc script also sets the prim dump interval (21.7 GB each). Every other output keeps the checkpoint's settings: hst every 0.01, prim, parbin and zprof every 1, uov every 10, rst every 25. From Oct 14 the 4 pc run writes rst every 5 (<output4> dt = 5 in athinput.restart_add) after a node failure; see Problems.

tigress_classic_LGR4_crmhd_8pc_rst.slurm
#!/bin/bash
#SBATCH --job-name=LGR4-cr8pc
#SBATCH --account=eost
#SBATCH --partition=cpu
#SBATCH -N 8
#SBATCH --ntasks-per-node=96   # 768 ranks = 768 meshblocks (BlockFFT: 1 block/rank)
#SBATCH --exclusive
#SBATCH --time=24:00:00        # site maximum since 2026-10-07 (QOS medium); chains via -r
#SBATCH --mail-type=all
#SBATCH --mail-user=changgoo@princeton.edu
#SBATCH --output=LGR4-cr8pc-%j.out
#
# LGR4 CRMHD, 8 pc: continue the production run from t = 450 to t = 550 with the
# shear-face positivity limiter (hydro + CR, eps = 0.5; no synchronised boundary fix)
# and the numerical-addition history columns.
#   mesh 128x128x1536 over +-512 x +-512 x +-6144 pc, 32^3 blocks -> 768 blocks
#   cost (crmhd-sync test with the sync fix, 2026-10-06): dt = 1.2e-4 (CR-limited), 1224 s per unit time
#
# Usage:
#   sbatch tigress_classic_LGR4_crmhd_8pc_rst.slurm        # first segment, from $SRC_RST
#   sbatch tigress_classic_LGR4_crmhd_8pc_rst.slurm -r     # continue from the run directory
#   env SUFFIX : exe suffix, tigris_crmhd_duale-blockfft-gcc-<SUFFIX>.exe [default: run, branch lgr4-crmhd-run]
#   env CC     : toolchain [default: gcc]
# Stops on the walltime soft limit (exit code 3) and resubmits itself with -r.
# After every segment it submits tigress_classic_postproc.slurm (quick-look frames + movies;
#   redraws all frames each time).

STARTFLAG=$1
CC=${CC:-gcc}
SUFFIX=${SUFFIX:-run}
TLIM=550

PID=TIGRESS
SLURMDIR=$HOME/tigris_scripts/tigress_classic/stellarai-amd
SCRIPT=tigress_classic_LGR4_crmhd_8pc_rst.slurm
TBLDIR=$HOME/tigris/inputs/tables
SRC_RST=/scratch/gpfs/EOST/$USER/tigress_classic_sync/rst/crmhd.00014.rst   # t = 450
RUNDIR=/scratch/gpfs/EOST/$USER/tigress_classic/LGR4-crmhd-8pc-t450
TWALL=23:30:00  # athena soft limit, inside the slurm limit

source "$SLURMDIR/env.sh"
load_toolchain "$CC" || exit 1
EXE=tigris_crmhd_duale-blockfft-${CC}-${SUFFIX}.exe
if [ ! -x "$SLURMDIR/$EXE" ]; then
    echo "ERROR: executable not found: $SLURMDIR/$EXE"
    echo "  build: build_tigress.sh --machine=stellarai-amd --cc=$CC --physics=crmhd_duale --grav=blockfft --worktree=<branch> --exe_suffix=$SUFFIX"
    exit 1
fi

if [[ $STARTFLAG != "-r" ]]; then
    if compgen -G "$RUNDIR/*.rst" > /dev/null; then
        echo "ERROR: $RUNDIR holds restart files; use -r"; exit 1
    fi
    mkdir -p "$RUNDIR"
fi
cd "$RUNDIR" || exit 1
cp "$SLURMDIR/$SCRIPT" "$SLURMDIR/$EXE" "$SLURMDIR/${EXE%.exe}.buildinfo" .
cp "$TBLDIR/tigress_coolftn.txt" "$TBLDIR/Z014_GenevaV00.txt" .

# Switches that are not in the t = 450 checkpoint's input.
cat > athinput.restart_add <<EOF
<hydro>
shear_flux_limiter     = true
shear_flux_limiter_eps = 0.5
<cr>
shear_flux_limiter     = true
shear_flux_limiter_eps = 0.5
EOF

set -o pipefail
if [[ $STARTFLAG != "-r" ]]; then
    # Production outputs of the checkpoint are kept (hst/phase_hst 0.01, prim/parbin/zprof 1,
    # uov 10, rst 25); history files start fresh in this directory.
    echo "Restarting from $SRC_RST (t = 450)"
    srun --cpu-bind=cores "./$EXE" -r "$SRC_RST" -i athinput.restart_add -t $TWALL \
        time/tlim=$TLIM output1/file_number=0 output5/file_number=0 \
        1> out.txt 2> err.txt
else
    RSTINPUT=$PID.final.rst
    [ -f "$RSTINPUT" ] || RSTINPUT=$(ls -1 $PID.[0-9]*.rst 2>/dev/null | sort | tail -1)
    if [ -z "$RSTINPUT" ]; then echo "ERROR: no restart file in $RUNDIR"; exit 1; fi
    rstnum=$(ls out*.txt 2>/dev/null | wc -l)
    echo "Restarting from $RUNDIR/$RSTINPUT"
    srun --cpu-bind=cores "./$EXE" -r "$RSTINPUT" -i athinput.restart_add -t $TWALL \
        1> out.r${rstnum}.txt 2> err.r${rstnum}.txt
fi
EXITCODE=$?
set +o pipefail
echo "EXITCODE = $EXITCODE"

if [[ $EXITCODE -eq 3 ]]; then
    echo "Resubmitting"
    cd "$SLURMDIR" && CC=$CC SUFFIX=$SUFFIX sbatch "$SCRIPT" -r
fi

# Quick-look figures and movies of everything written so far.
PPNAME=pp-$(basename "$RUNDIR")   # wait for any postproc of this run still queued or running
PPDEP=$(squeue -h -u $USER -n $PPNAME -o %i | paste -sd: -)
cd "$SLURMDIR" && sbatch -J $PPNAME ${PPDEP:+--dependency=afterany:$PPDEP} --ntasks-per-node=24 tigress_classic_postproc.slurm "$RUNDIR"

#!/bin/bash

#SBATCH --account=eost
#SBATCH --partition=cpu
#SBATCH -N 16
#SBATCH --ntasks-per-node=96   # 1536 ranks = 1536 meshblocks (BlockFFT: 1 block/rank)
#SBATCH --exclusive
#SBATCH --exclude=sai-n07n14   # node failures on 2026-10-14 and 10-16

#SBATCH --mail-type=all

#   refined checkpoint: tigris_tools refine-restart --refine 2 --block-size 64,64,32
#     (tigress_classic_sync/refine_4pc.slurm, 2026-10-07; conserved totals match 8 pc to 1e-15)
#   cost (test_4pc.slurm with the sync fix, 300 cycles): dt = 6e-5 (CR-limited), 0.535 s/cycle -> ~8900 s per unit
#   time, ~230 h for t = 100 -> about 10 segments of this 24 h job.
#
# Usage:
#   sbatch tigress_classic_LGR4_crmhd_4pc_rst.slurm        # first segment, from $SRC_RST
#   sbatch tigress_classic_LGR4_crmhd_4pc_rst.slurm -r     # continue from the run directory
#   env SUFFIX : exe suffix, tigris_crmhd_duale-blockfft-gcc-<SUFFIX>.exe [default: run, branch lgr4-crmhd-run]
#   env CC     : toolchain [default: gcc]

Post-processing

Frames and movies come from ~/TIGRESS-CR/python/plot_slices.py (changgoo/TIGRESS-CR at 62cefe7, plus the uncommitted plotting fix below), using pyathena master installed in editable mode.

The script runs on MPI ranks and loops over all prim snapshots. For each one it draws:

  • cr_snapshot_prj: projections;
  • cr_snapshot: slices;
  • cr_acoustic_plot;
  • cr_slices: CR slices;
  • snapshot.

It also computes PDFs (pdf, windpdf) and caches slices and projections as netCDF (allslc.{y,z}, prj.{y,z}; about 16 GB at 8 pc and 5.5 GB at 4 pc). Then it makes the movies in movies/. Every run redraws every frame.

  • Where the limiter applies. It works only with the shearing-periodic boundary, and the <cr> limiter only in the two-energy CR build (crmhd_duale).
  • What needs no input. The floor and ceiling fixes and all the numerical-addition history columns are always on.
